# ir-backend

大学の教学データ分析システム（IR支援アプリケーション）のバックエンドである。
フロントエンドの画面構築に対して、必要なデータを加工・計算して提供する REST API の役割を担う。

---

| カテゴリ | 技術 |
|---|---|
| フレームワーク | FastAPI |
| 言語 | Python 3.13 |
| DB アクセス | psycopg2 |
| データ処理 | pandas / NumPy |
| テスト | HTTP Client (`.http` ファイル) |

## アーキテクチャ概要

### フォルダ構成

```
ir-backend/
├── .env                   … DB接続情報などの設定値（※ Gitには上げない）
├── requirements.txt       … 使用するPythonライブラリの一覧
├── README.md
├── src/                   … ソースコード本体
│   ├── main.py            … アプリケーションの起動ファイル
│   ├── config.py          … 環境変数の読み込み
│   ├── datasource.py      … DBコネクションプールの管理
│   ├── db_connection.py   … SQLの実行処理
│   ├── routers/           … APIエンドポイントの定義
│   ├── models/            … リクエスト・レスポンスのデータ構造定義
│   └── services/          … データの加工・集計ロジック
└── tests/                 … テストコード
```

---

### 各フォルダに置くファイルの役割

| 種類 | フォルダ・ファイル | 置くもの | 役割 |
|---|---|---|---|
| API エンドポイント | `routers/` | ルーター（`〇〇.py`） | ブラウザやフロントエンドからアクセスされる URL に対応する処理の定義 |
| データ構造 | `models/` | Pydantic の `BaseModel` | API が受け取るデータ（リクエスト）や返すデータ（レスポンス）の形の定義 |
| ビジネスロジック | `services/` | サービス（`〇〇_service.py`） | ルーターから分離するデータの加工・計算・集計などの複雑な処理 |
| DB アクセス | `/` トップレベル | `datasource.py` 等 | コネクションプールの管理や SQL の実行処理 |
| 設定 | `/` トップレベル | `config.py` 等 | `.env` からの環境変数の読み込みや各種設定の管理 |

---

### データの流れ

リクエストを受けてからレスポンスを返すまでの流れは以下の通り。

```
クライアント（フロントエンド）
    ↓  HTTPリクエスト
routers/       … URLに対応する関数が呼ばれる
    ↓
services/      … データを加工・計算する（任意）
    ↓
datasource.py  … DBコネクションを取得する
    ↓
db_connection.py … SQLを実行し、結果を返す
    ↓
PostgreSQL     … データベース
```

### 命名規則

#### ファイル名

すべてスネークケース（小文字・アンダースコア区切り）で記述する。

| 種類 | パターン | 例 |
|---|---|---|
| ルーター | `〇〇.py` | `student.py`, `user_manage.py` |
| モデル | `〇〇.py`（ルーターと揃える） | `student.py`, `user.py` |
| サービス | `〇〇_service.py` | `student_service.py` |
| テスト | `test_〇〇.py` | `test_student.py` |

#### 変数・関数名
スネークケースで記述する。

#### エンドポイントURL
ケバブケース（小文字・ハイフン区切り）で記述する。
これはREST APIの一般的な慣習に従ったもので、URLではハイフンが単語の区切りとして広く認識されている。

### 新しいAPIを追加する手順

例：「学生の一覧を返す API」を追加する場合

1. `src/routers/` に 新しいルーター（`student.py`）を作成し、エンドポイントを定義する
2. `src/main.py` に 1で作成したルーターを `app.include_router()` で登録する
3. 必要に応じて `src/models/` に リクエスト/レスポンスのデータ定義（`student.py` 等）を作成する
4. 加工ロジックが複雑な場合は、`src/services/` に ロジック（`student_service.py`）を分離する
5. サーバーを起動し、ブラウザや `.http` ファイル等で動作確認する
